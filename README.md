# OmniProfit

Profit intelligence for a seller on several channels (marketplaces, own website, ONDC). Four agents turn raw orders into contribution margin per channel and per SKU, then propose actions. Every proposal passes through guardrails, and the whole system is also exposed as a Model Context Protocol (MCP) server.

## Agents

| Agent | Job | Uses a model? |
| --- | --- | --- |
| `IngestAgent` | Load and validate orders, fees, costs and ad spend; set bad rows aside with a reason | no |
| `CostAgent` | Revenue, cost of goods, channel fees, shipping and return cost for each order | no |
| `ProfitAgent` | Contribution margin by channel and by SKU within channel; ad spend allocated by revenue | no |
| `AdvisorAgent` | Propose actions, each citing one figure from the report | yes |

The figures are computed by code. The model only reads them and proposes.

## Guardrails

`src/omniprofit/guardrails.py` checks each proposed action before it is shown:

- The cited figure must match the computed report (so a model cannot invent a number).
- The channel and SKU must exist.
- Price rises are capped at 10% and ad cuts at 50%.
- A SKU can be paused on a channel only if it is losing money there and carries under 15% of revenue. Whole channels cannot be paused.
- The action type must be one of four allowed values; anything else fails schema validation.

Rejected actions are reported with the reason.

## Quick start

```bash
pip install -e ".[dev,mcp]"
omniprofit report --data data --skus
omniprofit recommend --data data
```

The data in `data/` is synthetic, generated by `scripts/make_sample_data.py`. Channel names are labels; the fee rates are made-up examples, not any marketplace's real rate card.

## MCP server

```bash
omniprofit serve-mcp --data data
```

This starts a stdio MCP server with three tools: `get_channel_profit`, `get_sku_profit(channel)` and `get_recommendations`. Example client configuration:

```json
{"mcpServers": {"omniprofit": {"command": "omniprofit", "args": ["serve-mcp", "--data", "/path/to/data"]}}}
```

## Using a real model

`recommend` defaults to an offline rule-based advisor (`src/omniprofit/mock.py`), which is not a model. Use `--provider ollama`, `groq`, `openrouter` or `openai` for a real one; its proposals go through the same guardrails.

## Cost model assumptions

A returned order earns no revenue and recovers its goods, but still pays outbound shipping, the fixed fee and a return-handling charge. Commission is treated as refunded on returns. Change `CostAgent` if your channels work differently.

## Tests

```bash
pytest -q
```

Includes a hand-calculated margin check, one test per guardrail, and a check that the MCP server registers its tools.
